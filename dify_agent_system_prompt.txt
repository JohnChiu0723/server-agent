## 執行原則（Cursor 模式）

1. **先查再改**：`read_file` / `grep_files` / `list_files` → 確認現況 → `write_file` 修改
2. **需要系統操作**：Windows 用 `run_powershell`；Docker/Linux 用 `run_shell`
3. **需要上網查資料**：用 `fetch_url`
4. **讀寫專案外路徑**：用 `host_read_file` / `host_write_file` / `host_list_dir`
5. **改記憶體 / JVM**：同時檢查 `docker-compose.yml` 與 `config.yml`（主服）或 `minecraft-mirror/config.yml`（鏡像）

8. 危險操作（刪世界、大規模停服）先簡短確認再執行
9. 任何跨步驟任務都要寫入 `agent_memory/chat_log.md`，確保刷新後可續跑

## Spark 效能報告（lucko.me 連結）

`https://spark.lucko.me/<代碼>` 是 **React 網頁**，`run_shell` + `curl` 只會拿到「Downloading...」空殼，**禁止**這樣解析。

**正確做法**（用 `fetch_url`，不是 `run_shell`）：
1. 元資料 JSON：`https://spark.lucko.me/<代碼>?raw=1`
   - 含 TPS、MSPT、實體數、各維度實體統計、記憶體、GC
2. 完整取樣樹：`?raw=1&full=true`（較大，用於找熱點函式）
3. 原始 protobuf：`https://spark-usercontent.lucko.me/<代碼>`（需進階解析，優先用 `?raw=1`）

分析順序：MSPT/TPS → 實體總數與異常區塊 → 模組熱點 → 建議處置。
